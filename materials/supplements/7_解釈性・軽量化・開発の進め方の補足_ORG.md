## 1. モデルの解釈性（公式テキスト p.312〜314）

### CAM（p.312）
- **説明**：Class Activation Mapping の略。画像分類のCNNで、あるクラスと判断するときに、画像のどの領域が強く影響したかを**ヒートマップ**（影響の強さを色の濃さで表した図）で示す方法。
- **しくみ**：最後の畳み込み層の特徴マップを、そのあとの全結合層の重み（そのクラスに対する重み）で重み付けして足し合わせる。
- **制約**：最後の畳み込み層のあとに**Global Average Pooling**（特徴マップ全体の平均をとる層）を置き、すぐ全結合層につなぐ構造のCNNでなければ、そのままでは使えない。

### Grad-CAM（p.313）
- **説明**：CAMを発展させた方法。特徴マップの重み付けに、そのクラスの出力に対する**勾配**を使う。
- **CAMとの違い**：勾配を使うので、Global Average Pooling を持たない構造のCNNにも、作り直さずに適用できる。
- **関連する語**：Guided Grad-CAM（p.314）は、Grad-CAMと、より細かい輪郭を示す方法を組み合わせ、判断に効いた部分を高い解像度で示す。
- **注意**：CAMやGrad-CAMは「どこを見て判断したか」を示すものであり、判断が正しいことを保証するものではない。

### Permutation Importance（p.312）
- **説明**：学習済みのモデルで、ある特徴量の値だけをデータ間でランダムに並べ替え（シャッフルし）、予測の精度がどれだけ下がるかを調べる。精度が大きく下がる特徴量ほど、モデルにとって重要だとみなす。
- **特徴**：
  - モデルの種類を問わずに使える（モデルの中身を見ずに、入力と出力だけで計算できる）。
  - モデル全体として、どの特徴量が重要かを示す（大域的な説明）。
- **LIMEとの違い**：LIME（p.312）は、ある1件の予測について、その周辺で単純なモデルを当てはめ、その予測にどの特徴量が効いたかを示す（局所的な説明）。
- 格納テキスト第7章 7.4節（XAI）とあわせて理解する。
- **公式テキストでの説明（p.312「説明可能AI」）**：モデルがどのように判断しているかを解釈するために、入力データの特徴の一部だけを与え、その時の振る舞いを線形モデルに近似するLIMEがあり、Permutation Importanceでは、入力データの特徴をランダムに入れて、振る舞いの変化をもとに特徴の寄与度を測る、と書いている。SHAPも特徴量の寄与度を測ることでモデルの解釈を行い、これらはディープラーニング以外の機械学習全般で利用されている。一方で、計算コストが高かったり、特徴間の相関が高かったりすると、寄与度を測るのが難しくなる、としている。公式テキストは「大域的な説明／局所的な説明」という分け方をしていない（この分け方は公式テキストにない補足）。
- **確認欄**：照合済み（2026年11月11日に公式テキスト p.312 と照合）

## 2. モデルの軽量化（公式テキスト p.315〜317、p.333）

### モデル圧縮（索引なし。関連：蒸留 p.315・枝刈り p.316・量子化 p.317）
- **説明**：精度をなるべく保ったまま、モデルの大きさ（パラメータの数やメモリ）や計算量を減らす技術の総称。
- **代表的な方法**：
  - **枝刈り（プルーニング）**：重要度の低い重みやニューロンを取り除く。
  - **量子化**：重みなどの数値を表すビット数を減らす（例：32ビットの小数を8ビットの整数にする）。
  - **蒸留（知識蒸留）**：学習済みの大きなモデル（教師モデル）の出力をお手本にして、小さなモデル（生徒モデル）を学習させる。
- **目的**：スマートフォンや組み込み機器など、計算資源の限られた環境でモデルを動かすため。
- 格納テキスト第6章の章末整理で、プルーニング・量子化・知識蒸留に一言触れている。

### 宝くじ仮説（p.317）
- **説明**：大きなニューラルネットワークの中には、学習前の初期値のまま取り出して単独で学習させても、元のネットワークと同じくらい（またはそれ以下）の学習回数で、同じくらいの精度に達する小さなサブネットワーク（「当たりくじ」）が含まれている、という仮説（FrankleとCarbinによる研究。2019年の国際会議ICLRで発表された）。
- **意味**：大きなネットワークの多くの重みは、性能にとって必ずしも必要ではない可能性を示す。枝刈りで小さなモデルを作る研究の根拠の1つになっている。
- **公式テキストでの説明（p.316〜317「枝刈り」）**：枝刈りは、モデル全体の学習と枝刈りを繰り返して少しずつモデルサイズを圧縮することが多い（いきなり多くの重みを削除してしまうと精度に悪影響を及ぼすため）としたうえで、宝くじ仮説では、モデルを学習する際に、より良い初期値（当たりくじ）を持つサブネットワークがモデル全体の中に含まれているという考え方をしており、このサブネットワークが枝刈りしたモデルに相当する、と書いている。枝刈り後のモデルの初期値には元のモデルの値を利用して学習する。従来の枝刈りでは枝刈り後のモデルの重みを初期化せず繰り返し更新するのに対し、宝くじ仮説では、枝刈りを行って学習する際に重みを初期値に戻す（巻き戻す）。学習と枝刈りを繰り返すよりも、重みを巻き戻した方が高い精度になることが示されている、としている。研究者名と発表した会議は公式テキストにない補足。
- **確認欄**：照合済み（2026年11月11日に公式テキスト p.316〜317 と照合）

### エッジAI（p.333）
- **説明**：スマートフォン、監視カメラ、自動車、工場の機器など、データが発生する現場に近い端末（エッジ）でAIの推論を行うこと。データをクラウドに送って処理する**クラウドAI**と対比される。
- **利点**：
  - クラウドとの通信の待ち時間を減らせるので、すぐに結果が出る（リアルタイム処理に向く）。
  - 送るデータが減るので、通信量や通信の費用を抑えられる。
  - 通信できない場所でも動かせる。
  - データを外に送らずに済むので、プライバシーの保護に役立つ場合がある。
- **課題**：端末の計算資源や電力には限りがあるので、モデル圧縮などで軽量化する必要があることが多い。

## 3. AIプロジェクトの進め方（公式テキスト p.331〜344）

### BPR（p.332）
- **説明**：Business Process Re-engineering（ビジネスプロセス・リエンジニアリング）の略。業務の流れ（プロセス）を根本から見直し、作り直すこと。
- **AIとの関係**：AIを導入するとき、今の業務のやり方のままAIを部分的に当てはめるだけでは、効果が限られることがある。AIを前提に、業務の流れそのものを見直すことが重要になる。
- **公式テキストでの説明（p.332「AIを適用した場合のプロセスを再設計する」）**：AIを利活用する場合はBPR（Business Process Re-engineering）が発生するとし、現業務プロセスがアナログ空間にいる"人"が実行することが前提のプロセスである場合、AIを利活用するプロセスに変更する必要があるため、と書いている。まず現プロセスのコストとAI導入後のコストを算出し、それぞれが乖離する（特にAI導入後のコストが増大する）場合は、AIの適用箇所と技術の連携範囲を再検討する必要がある。例として、工場での外観検査の自動化で、人が検査と同時に製品を別の場所に運ぶ作業も行っている場合、検査だけをAI化すると運ぶ作業は人が行うままで人件費削減にならない。これは今までの業務プロセスをそのまま活かそうとしたために起きるもので、「検品＋移動」を別々に分けて考え、それぞれのプロセスを設計し直すことで解決できる。また、AIシステムは進化するので、フィードバックによるAIの推論精度の向上により業務プロセスを徐々に変化させることも必要、としている。
- **確認欄**：照合済み（2026年11月11日に公式テキスト p.332 と照合）

### ウォーターフォール・アジャイル（索引なし。シラバスのキーワードとしては2語）
- **ウォーターフォール**：要件定義 → 設計 → 実装 → テスト → 運用 のように、工程を上から下へ順に進める開発の進め方。原則として前の工程に戻らない前提で計画する。最初に仕様がはっきり決まる開発に向く。
- **アジャイル**：短い期間で「計画 → 開発 → 確認」を何度も繰り返し、途中で分かったことを取り入れて、仕様を柔軟に変えながら進める開発の進め方。
- **AI開発との関係**：AI開発では、データを集めて学習させてみるまで、どれだけの精度が出るかが分からない。そのため、最初にすべてを決めるウォーターフォールだけでは進めにくく、試行錯誤を前提にした反復的な進め方が使われることが多い。
- 格納テキスト第7章 7.1節（PoCを含むサイクル）と、補遺「法律と契約」の「探索的段階型の開発」とあわせて理解する。

### Python（p.344）
- **説明**：機械学習やデータ分析で最もよく使われるプログラミング言語。文法が読みやすく、書いたコードをすぐに実行して確かめやすい。
- **主なライブラリ**：NumPy（数値計算）、pandas（表形式のデータの処理）、scikit-learn（機械学習）、TensorFlow・PyTorch（ディープラーニング）、Matplotlib（グラフの作成）。

### Jupyter Notebook（索引なし）
- **説明**：ブラウザ上で、プログラムを小さな単位（セル）ごとに実行し、その結果（表やグラフ）をその場で確かめながら、説明の文章と一緒に記録できる対話型の開発環境。
- **使いどころ**：データ分析やモデル作りの試行錯誤。分析の過程を、ほかの人と共有しやすい。
- **関連する語**：Google Colaboratory は、同じような環境をクラウド上で使えるサービス。

### Docker（索引なし）
- **説明**：アプリケーションと、その実行に必要なライブラリや設定を**コンテナ**という単位にまとめ、どのコンピュータでも同じように動かせるようにする仕組み（コンテナ型の仮想化）。
- **使いどころ**：「開発者のパソコンでは動いたのに、本番のサーバーでは動かない」といった、環境の違いによる問題を減らす。学習や推論の環境を、ほかの人やサーバーに再現しやすくなる。
- **仮想マシンとの違い**：仮想マシンはOSごと再現するが、コンテナは土台のOSの中心部分（カーネル）を共有するので、軽く、すぐに起動できる。

### Web API（索引なし）
- **説明**：ネットワーク（主にHTTP）を通じて、ほかのプログラムから機能を呼び出せるようにした窓口。
- **AIとの関係**：学習済みのモデルをWeb APIとして公開すると、利用する側はモデルの中身や実行環境を用意しなくても、データを送るだけで予測結果を受け取れる。クラウド事業者が提供する画像認識や音声認識のAPIが、その例。

## 5. 数理・統計（索引なし）

### 度数分布（索引なし）
- **説明**：データを値の範囲（**階級**）ごとに区切り、それぞれの階級に入るデータの個数（**度数**）を数えて整理したもの。表にしたものを**度数分布表**、棒グラフのように表したものを**ヒストグラム**と呼ぶ。
- **関連する語**：
  - **相対度数**：ある階級の度数を、データ全体の個数で割った値（全体に占める割合）。すべての階級の相対度数を足すと1になる。
  - **累積度数**：最初の階級から、ある階級までの度数を足し合わせた値。
- **使いどころ**：データの分布の形（どのあたりに集中しているか、偏りや外れ値がないか）をつかむ。
- **注意**：階級の幅の決め方によって、分布の見え方が変わる。
- **計算の例**：50人の得点で、「60点以上70点未満」の階級の度数が12人なら、相対度数は 12 ÷ 50 ＝ 0.24。

## 取り違えやすい組（用語確認ドリルの誤答に使う）

| 組 | 違い |
|---|---|
| CAM ／ Grad-CAM | 全結合層の重みを使い、Global Average Pooling を持つ構造が前提 ／ 勾配を使い、多様な構造のCNNに使える |
| Permutation Importance ／ LIME | 特徴量を並べ替えたときの精度の下がり方で、モデル全体の重要度を見る ／ 1件の予測の周辺で、どの特徴量が効いたかを見る |
| 枝刈り ／ 量子化 ／ 蒸留 | 重要でない重みを取り除く ／ 数値のビット数を減らす ／ 大きなモデルをお手本に小さなモデルを学習させる |
| エッジAI ／ クラウドAI | 現場の端末で推論する ／ データをクラウドに送って処理する |
| ウォーターフォール ／ アジャイル | 工程を順に進め、前に戻らない前提 ／ 短い反復を繰り返し、仕様を柔軟に変える |
| Jupyter Notebook ／ Docker ／ Web API | 対話的に実行・記録する開発環境 ／ 実行環境をコンテナにまとめる仕組み ／ ネットワーク経由で機能を呼び出す窓口 |
| 度数 ／ 相対度数 ／ 累積度数 | 階級に入る個数 ／ 全体に占める割合 ／ 最初の階級からの合計 |
