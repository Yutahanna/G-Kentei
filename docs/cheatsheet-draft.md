## 1. 評価指標・計算（3-7）

|  | 予測：陽性 | 予測：陰性 |
|---|---|---|
| **実際：陽性** | TP（真陽性） | FN（偽陰性＝見逃し） |
| **実際：陰性** | FP（偽陽性＝誤検出） | TN（真陰性） |

| 指標 | 式 | 重視する場面 |
|---|---|---|
| 正解率 Accuracy | (TP+TN) / 全体 | 不均衡データでは実態を見誤りやすい |
| 適合率 Precision | TP / (TP+FP) | 誤検出（FP）を避けたい |
| 再現率 Recall（＝TPR） | TP / (TP+FN) | 見逃し（FN）を避けたい（例：病気） |
| F値 F1 | 2·P·R / (P+R) | 適合率と再現率の調和平均 |
| ROC曲線 | 横軸FPR・縦軸TPR | 閾値を変えたときの変化。左上ほど良い |
| AUC | ROCの下側面積（0〜1） | ランダムな予測≒0.5、完璧≒1。閾値に依存しない |

- 適合率と再現率はトレードオフになりやすい（判定を緩めると再現率↑・適合率↓）。（3-7）
- **ベイズの定理**：事後確率 ∝ 事前確率 × 尤度。事前確率が低いと、陽性の多くが偽陽性になりうる。応用例はナイーブベイズ（迷惑メールフィルタ）。（8.3）
- **損失関数**：回帰には平均二乗誤差、分類には交差エントロピー誤差（自信満々の誤答を強く罰する）。（8.5）
- 交差エントロピー ＝ 正解分布のエントロピー ＋ KLダイバージェンス。前者は定数なので、交差エントロピーを最小化することはKLの最小化と同じ意味になる。（8.4）
- 第一種の誤り＝正しい帰無仮説を棄却する誤り。第二種の誤り＝誤った帰無仮説を棄却できない誤り。p値は「帰無仮説が正しい確率」**ではない**。（第8章 章末）

## 3. 深層学習の部品（第4章・5.11〜5.12）

**活性化関数（4.4）**

| 関数 | 出力の範囲 | ポイント |
|---|---|---|
| シグモイド | 0〜1 | 勾配消失を起こしやすい |
| tanh | −1〜1 | 0を中心に出力。シグモイドより安定しやすい |
| ReLU | 0以上 | 正の領域では傾きが1で勾配消失しにくい。現在の主流。dying ReLUの問題がある → Leaky ReLU |
| softmax | 合計が1 | 多クラス分類の出力層。交差エントロピーと組み合わせる |

**最適化手法（5.12、4章 章末）**

| 手法 | 特徴 |
|---|---|
| SGD | ミニバッチ単位で更新する |
| Momentum | 慣性を加えて振動を抑え、収束を速める |
| AdaGrad | パラメータごとに学習率を調整する。ただし学習率が減衰しすぎる |
| RMSprop | 学習率調整を工夫した手法 |
| Adam | Momentum＋AdaGradの発想（2014年）。現在の標準 |

**混同しやすい組（4章・5章・8章 章末）**

| 組 | 違い |
|---|---|
| 誤差逆伝播法／勾配降下法 | 勾配を**求める**方法／勾配を使って**更新**する方法 |
| 正則化／正規化 | 過学習を抑える／値の範囲や分布をそろえる |
| L1／L2正則化 | 重みを0にしやすい（変数選択、Lasso）／全体を滑らかに縮める（Ridge） |
| Dropout／Batch Norm | 学習時にニューロンをランダムに無効化／ミニバッチ単位で正規化（副次的に正則化の効果もある） |
| バッチ正規化／レイヤー正規化 | CNNで代表的／Transformerで代表的 |
| Xavier初期化／He初期化 | シグモイド・tanh系／ReLU系 |
| バギング／ブースティング | 並列に独立して学習（ランダムフォレスト）／直列に前の誤りを補う（AdaBoost、勾配ブースティング） |
| バイアス／バリアンス | 単純すぎることによる誤差／複雑すぎてノイズに反応することによる誤差 |
| 訓練／検証／テストデータ | 重みの学習／ハイパーパラメータの調整／最終評価だけに使う |
| 標準化／正規化／白色化 | 平均0・標準偏差1にする／一定範囲に収める／相関を除いて分散もそろえる |
| k-means／PCA | 行（データ点）をまとめる／列（変数）をまとめる |

## 4. モデルの系譜「何の弱点を解いたか」

**CNN（5.1）**：LeNet →（深さ）AlexNet：ReLU・Dropout・GPU → VGG：3×3を深く重ねる → GoogLeNet：Inceptionで並列化 → ResNet：スキップ接続

**系列モデル（5.2〜5.3）**

| モデル | 解いたこと／残った弱点 |
|---|---|
| RNN | 隠れ状態で過去を記憶する。長期依存は苦手（BPTTで勾配消失が起きる） |
| LSTM | 入力・忘却・出力の**3ゲート**＋セル状態 |
| GRU | 更新・リセットの**2ゲート**で軽量化 |
| Transformer | 逐次処理をやめて並列化。Self-Attention・Multi-head・Positional Encoding |

- Q・K・V：Query＝探す条件、Key＝照合する情報、Value＝取り出す内容。（5章 章末）

**BERTとGPTの比較（5.5）**

|  | BERT | GPT |
|---|---|---|
| 構造 | エンコーダーのみ | デコーダーのみ |
| 方向 | 双方向 | 一方向 |
| 事前学習 | マスク言語モデル | 次単語予測 |
| 得意なこと | 理解（分類・抽出） | 生成 |

- スケーリング則：規模（モデル・データ・計算量）を増やすと性能が予測可能な形で向上する。創発的能力：規模が閾値を超えると急に現れる能力。（5.5）

**生成モデル（5.6）**

| 手法 | 仕組み | 長所／短所 |
|---|---|---|
| GAN | 生成器と識別器を競わせる | 高品質だが学習が不安定 |
| VAE | オートエンコーダーを確率分布に拡張 | 学習は安定だが生成物がやや不鮮明 |
| 拡散モデル | ノイズを段階的に除去する過程を学習 | 現在の画像生成の主流 |

**画像タスク（6.1〜6.2、6章 章末）**

| タスク | 出力 | 代表モデル |
|---|---|---|
| 画像分類 | 画像全体のカテゴリ | CNN |
| 物体検出（2段階、精度重視） | カテゴリ＋矩形 | R-CNN → Fast R-CNN → Faster R-CNN |
| 物体検出（1段階、速度重視） | カテゴリ＋矩形 | YOLO、SSD |
| セマンティックセグメンテーション | ピクセルごとのカテゴリ | U-Net、FCN、SegNet、DeepLab、PSPNet |
| インスタンスセグメンテーション | 個体を区別した領域 | Mask R-CNN |
| パノプティックセグメンテーション | 背景領域＋個体領域 | ― |

**生成AIの運用（5.7〜5.9）**
- RLHFの3段階：①SFT（教師ありファインチューニング）→ ②報酬モデルの学習（人間による順位付け）→ ③強化学習（PPOなど）。（5.7）
- Zero-shot／Few-shot／Chain-of-Thoughtは、いずれも**重みを更新しない**。重みを更新するのはファインチューニング。（5.8）
- RAG：検索結果をプロンプトに入れて回答させる。最新の情報や社内情報への対応、出典の提示に有効。ただしハルシネーションはゼロにならない。（5.9）

**強化学習（6.5、3章 章末）**：Q学習＝Q値（行動の価値）を推定する／方策勾配法＝方策を直接調整する／DQN＝Q学習＋深層学習／Actor-Critic＝方策（Actor）＋価値（Critic）／バンディット・UCB＝探索と活用のバランス

**自然言語処理の文書表現（6章 章末）**：BoW・N-gram・TF-IDF（古典的な表現）／word2vec：CBOW＝周辺語から中心語を予測、Skip-gram＝中心語から周辺語を予測

**軽量化（6章 章末）**：プルーニング＝重みの削除／量子化＝数値精度を下げる／知識蒸留＝大きな教師モデルから小さなモデルへ知識を移す

## 5. 社会実装（第7章）

- プロジェクトの流れ：企画 → PoC → データ収集・前処理 → 開発 → 実装 → 運用。PoCはゴールではない（評価基準がないと「PoC貧乏」になる）。（7.1）
- データドリフト＝入力分布の変化／**コンセプトドリフト**＝入力と正解の関係の変化。対策はMLOps（監視・再学習）。（7章 章末）
- データリーケージ：予測時には使えない情報やテストデータの情報が学習に漏れ、見かけの精度が上がる問題。（7章 章末）
- CRISP-DM：ビジネス理解 → データ理解 → データ準備 → モデリング → 評価 → 展開。（7章 章末）
- XAI：LIME＝個別の予測について局所的に説明する／SHAP＝ゲーム理論の考え方で、より厳密に貢献度を計算する。（7.4）
- データの偏り：サンプリングバイアス／アノテーションバイアス／社会的バイアス。（7.2）

## 6. 法律（第9章）—「誰が・どのデータを・何の目的で・どの段階で」

**個人情報保護法（9.1）**

| 区分 | ポイント |
|---|---|
| 個人情報 | 生存する個人を識別できる情報（容易に照合できるものを含む） |
| 個人データ | データベース化され検索できる状態 → 安全管理措置などの義務が強まる |
| 保有個人データ | 開示・訂正・削除の権限がある → 本人の開示請求などが及ぶ |
| 要配慮個人情報 | 人種・信条・病歴・犯罪の経歴など → 取得時に原則として本人の同意が必要 |

|  | 匿名加工情報 | 仮名加工情報 |
|---|---|---|
| 加工 | 個人を識別できず、**復元もできない** | 照合しなければ識別できない（社内では戻せる） |
| 第三者提供 | 本人の同意なしで**可能** | 原則として**制限** |
| 重視すること | 外部に提供する自由 | 社内利用の柔軟性 |

- GDPR：域外適用がある。自動化された意思決定への関与権がある。日本法より厳格とされる。（9.1）

**著作権法（9.2）**

| 段階 | 考え方 |
|---|---|
| 学習段階 | **30条の4**：情報解析など「享受を目的としない利用」は原則として許諾不要 |
| 30条の4の限界 | 享受目的の利用には及ばない／著作権者の利益を不当に害する場合は除外されうる（例：有償の学習用データベースを無断でスクレイピングする） |
| 生成・利用段階 | 通常の著作物と同じルール。既存の著作物に似すぎていれば侵害が問題になる（依拠性と類似性） |
| AI生成物の著作物性 | 人間の創作的関与の有無と程度で判断する |

- 著作権法が保護するのは「表現」で、「アイデア」は保護しない。（9.2）

**特許・著作権・営業秘密（9.3）**

|  | 特許権 | 著作権 | 営業秘密 |
|---|---|---|---|
| 対象 | 発明（自然法則を利用した技術的思想の創作） | 創作的な表現 | 秘密にしている情報 |
| 発生 | 出願・審査・登録 | 創作した時点で自動的に発生（無方式） | 3要件を満たすこと |
| 公開 | 原則として公開 | 公開が前提 | 非公開が前提 |
| 期間 | 有限 | 有限（比較的長い） | 秘密である限り続く |

- 営業秘密の3要件：**秘密管理性・有用性・非公知性**（争点になりやすいのは秘密管理性）。（9.4）
- 限定提供データ：秘密管理されていなくても、限定して提供され、相当量蓄積され、電磁的に管理されたデータを保護する。（9章 章末）
- 独占禁止法：**優越的地位の濫用**（例：データ提供の強要）。（9.5）
- 契約：請負＝完成義務／**準委任**＝善管注意義務（成果が不確実なAI開発で使われやすい）。NDA＝秘密保持契約。（9.6、9章 章末）
- AI・データ契約ガイドライン（経済産業省）：アセスメント → PoC → 開発 → 追加学習の「探索的段階型」。（9.6）
- PL法：過失がなくても責任を負う。対象は有体物。AIソフトウェア単体が対象になるかは議論があるが、製品に組み込まれていれば対象になりうる。（9.7）

## 7. 倫理・ガバナンス（第10章）

| 項目 | ポイント |
|---|---|
| AI事業者ガイドライン | 総務省と経済産業省が策定。**開発者・提供者・利用者**の3層。マルチステークホルダーで検討。**法的強制力はない** |
| 人間中心のAI社会原則 | 日本政府の理念文書。人間の尊厳・多様な幸福・持続可能性 |
| G7広島AIプロセス | 日本が議長国。生成AIの国際指針と行動規範 |
| EU AI Act | **リスクベースアプローチ**（禁止：社会的スコアリング／ハイリスク：採用・信用スコア → 厳格な義務／チャットボット → 透明性義務） |
| 米国 | 大統領令など機動的な手段を使う |

- 各地域のスタンス：EU＝法規制、日本＝ガイドライン（ソフトロー）、米国＝大統領令。（10.4）
- 基本原則：公平性・透明性・説明責任・プライバシー保護・安全性。（10.5）
- 代理変数：郵便番号などが性別や人種を間接的に表してしまう変数。（10章 章末）
- ハードロー＝法的強制力がある規制／ソフトロー＝ガイドラインや自主規制。（10章 章末）
- プライバシー・バイ・デザイン：設計段階からプライバシー保護を組み込む。（10章 章末）
- 攻撃の種類：データ汚染（学習段階を狙う）／モデル窃取（モデルの機能を盗む）／メンバーシップ推論（学習データに含まれるかを推定する）／モデル反転（データの特徴を復元する）。（10章 章末）
- フィルターバブル＝個人最適化によって異なる情報に触れにくくなる／エコーチェンバー＝同質な集団の中で意見が増幅される。（10章 章末）
- ディープフェイク対策：技術的な対策（電子透かし・来歴情報・検知）と社会的な対策（リテラシー教育）の両方が必要。（10.7）
